# 机场配置分析目录

本目录包含对不同机场订阅配置的离线分析和模块化拆分。

## 目录结构

```
verge/analysis/
├── airport-a/          # 机场A（原 机场A）
│   ├── modules/        # 模块化拆分后的配置
│   └── ori-*.yaml      # 原始订阅文件（已脱敏，不提交到 git）
├── airport-b/          # 机场B（原 机场B）
│   ├── modules/        # 模块化拆分后的配置
│   └── ori-*.yaml      # 原始订阅文件（已脱敏，不提交到 git）
└── README.md           # 本文件

```

## 机场映射说明

| 目录名 | 原机场名 | 特征 | 节点数 | 规则数 |
|--------|----------|------|--------|--------|
| `airport-a/` | 忍者云 | 规则详细，广告拦截 44,000+ 条，策略组 26 个 | 48 个 | ~52,000 |
| `airport-b/` | 机场B | 规则精简，大量域名走 🔰 选择节点，策略组 11 个 | 47 个 | ~9,600 |

## 本地识别方式

由于隐私脱敏要求，目录使用匿名标识（airport-a/airport-b）。
**本地识别方法：**

1. **查看本地原始文件**：`ori-airport-a-rule-split.local.yaml` 和 `ori-airport-b-rule-split.local.yaml`
   - 这些文件包含原始的节点信息，可以识别是哪个机场

2. **根据特征识别**：
   - 规则数量多 + 策略组详细 = airport-a（忍者云）
   - 规则精简 + 大量走节点选择 = airport-b（机场B）

3. **查看本机备忘录**：建议在本地笔记中记录映射关系

## 脱敏原则

- **不提交到 git**：`ori-*.yaml` 原始订阅文件（含节点信息）
- **可提交到 git**：`modules/` 目录下的模块化文件（仅含规则分流逻辑，无节点密钥）

## 使用方式

各机场的模块化配置用于：
1. 分析其规则物料和分流逻辑
2. 反哺到主配置（`verge/derive/parts/`）
3. 对比不同机场的配置风格差异
