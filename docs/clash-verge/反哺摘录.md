## 阶段 4：片段化产物（`refactor-p04/fragments/`）

- 片段按「首次出现 `# --- …` 分界行」切分；**首段**含 `rules:`、域名类说明注释与全部域名类规则，直至 IPv4 段注释之前。
- **合并自检**：在同一目录运行 `python3 verify_phase04_concat.py`，串联结果应与 `refactor-p03/clash-after-phase03.local.yaml` 中自 `rules:` 起的字节流完全一致。
- **手工合并**：在主 Profile 单一的 `rules:` 下列出各片段文件的行（从上到下按文件名序号 `00`、`01`、`02`……），勿重复写入第二个顶层 `rules` 键。
- **子 Agent 复查结论存档**：仓库内 `REFACTOR-AGENT-SIGNOFF.md`（分段结论：均为通过）。
- **局限（与「按规则类型模块化」目标不完全一致）：** 下节「再规划」——当前片段以 **Phase 2 注入的 `# ---` 首见类型** 为界；**不能**保证每个片段内规则类型单一（见下「`00` / `01`」）。

## 模块化拆分再规划（双轨：A 单文件 + B 多规则集）

日常同时保留两条线即可：

| 轨道 | 给谁用 | 形态 |
|------|--------|------|
| **A** | Verge **全局扩展粘贴**、与现有 `render-local.sh` 一致 | **单份** `*-rule-split.local.yaml`（模板渲染 + 可选本地片段注入）；大表可继续在仓库侧用脚本 **拼接** 后再粘贴，不要求 Mihomo 自己去读多文件。 |
| **B** | Mihomo **`rule-providers` + `RULE-SET`** | **主编排**（短 `rules:` 只负责 **引用顺序与策略组**）+ **多份 classical 规则集文件**（每份 `payload:` 下放与现稿相同的 `- TYPE,...` 行）。路径需落在 Verge/Mihomo 配置目录可被 `./ruleset/...` 解析的位置，或通过 `http(s)` 拉取。 |

### `04`、`05` 是否单独成文件？

- `04`（`GEOIP`）与 `05`（`MATCH`）在现稿里各 **一行**，拆成独立文件 **对维护几乎无增益**，还会在主编排里多两个无意义的文件名。
- **建议：** 在 **B** 的主配置里 **直接写** 这两条；模块化精力放在「大段」：`DOMAIN*` / `IP-CIDR*` / `PROCESS*` / `RULE-SET` 等。
- **A** 仍是一张整表，`GEOIP` / `MATCH` 本来就在文末，无需动。

### 为何感觉 `00` 与 `01`「里面什么都有」？

- **`00-rules-before-ipv4markers`：** 从 `rules:` 起一直到（不含）**第一条** `# --- IPv4 段（多在域名规则之后）---` 之前。主体是 **主机名类**（`DOMAIN` / `DOMAIN-SUFFIX` / `DOMAIN-KEYWORD` / `RULE-SET` 等），与 Phase 2 注释「域名类规则」一致。
- **`01-ipv4-段-…`：** 从 **该 IPv4 段注释行** 起切分；设计意图是「IPv4 / `IP-CIDR` 起步」。但 **订阅原稿在注释之后仍插入了大量 `DOMAIN-SUFFIX` 等主机名规则**（与 `IP-CIDR` 交错），因此 **不是「纯 IP 段文件」**，看起来又像「什么都有」——这是 **数据源在注释边界后继续混排** 所致，**不是** Phase 4 把类型拆乱了。
- 结论：若目标是 **「按规则类型模块化」**，不宜再沿用「仅按 `# ---` 首见类型分界」作为主要切分逻辑；应改用下面 **按类型 + 保序** 的策略。

### 按规则类型模块化时，必须坚持「全文顺序不变」

- Clash/Mihomo 规则是 **从上到下首条命中**；若把「所有 `DOMAIN-SUFFIX` 抽到一个文件、所有 `IP-CIDR` 抽到另一个文件」，再在主编排里先引用 A 再引用 B，会 **改变** 原稿里「一段 IP、又一段域名」的交错顺序，**分流结果可能变**。
- **安全做法：** 在主配置中用 **一串 `RULE-SET,片段名,策略组`（或每段对应策略）**，使 **各片段在链上的顺序 = 原 `rules` 列表中的顺序**。
- **推荐桶（生成脚本用）：** 在 **保持原顺序** 的前提下，把列表扫成 **极大连续段**，每段标一个 **主类型桶**（用于命名与维护，而不是把同类型全库合并）：
  - **hostname**：`DOMAIN` / `DOMAIN-SUFFIX` / `DOMAIN-KEYWORD` / `DOMAIN-WILDCARD` / `DOMAIN-REGEX`（若出现）——**同一段内允许并存**（与现网「主机名规则」心智一致）。
  - **ip4**：连续 `IP-CIDR`（可带 `no-resolve`）。
  - **ip6**：连续 `IP-CIDR6`。
  - **process**：连续 `PROCESS-NAME` / `PROCESS-PATH`（若有）。
  - **ruleset_inline**：连续 `RULE-SET`（与远程规则集不同，仍是逐行列）。
  - **geo / final**：通常各一行；**直接写在主编排** `rules:` 里即可，**不必**单独 `rule-provider`。
- 若某段内部仍混了「本不应同段」的类型（历史脏数据），脚本可 **降级** 为 **按「实际行类型」再切子段**，或保留该连续块为 `mixed-NN` 单文件，直到人工整理订阅源。

### 与现 `refactor-p04/fragments/` 的关系

- 现有 `00`～`05` 片段 **继续可用作「阅读 / 对照 / 合并自检」**（与 `verify_phase04_concat.py` 一致）。
- **B 轨**（rule-providers 模块化）的生成本目录约定为：**`refactor-p04-rule-providers/`**（与 `refactor-p04/` 同级）；生成物可复制到 Mihomo `./ruleset/` 或通过 `path` / `http` 引用。**按代理分组拆分**或其它策略由该目录内脚本实现，见同级 `README.md`。
- **A 轨** 仍可走 `verge/generated/*-rule-split.local.yaml` 或与 **按组导出后再拼接**；两者可并存。

## 命名与语义


- **「应用净化」与遥测：** 在民间规则集习惯里，`应用净化`（本稿中 Emoji 为 `🍃`）主要收纳 **应用内向「统计/报表/联运回传」等请求域名**，与日常所说的 **遥测／应用遥测（采集运行数据的上报链）** 最接近；书面说明里优先使用上述中文，避免夹带不必要的英文日常词。
- **「广告拦截」：** 对应 `🛑`，偏 **第三方广告联盟、展示类追踪**；与遥测条目在数据源上常有交叉，但以 **清单分区**区分，便于面板里一键「只关一类」。
- **命中顺序：** 二者若同时命中多条规则，仅以 **文件中更靠上的一条**为准；重复的第二条策略**不会生效**——整理稿时删减重复行不会改变对外表现。

## 阶段整理中的量化发现（阶段 1）

- 原版约 **5.3 万**条 `rules`，其中 **域名后缀类** (`DOMAIN-SUFFIX`) 是绝对主体；删减 **498** 条仅包含：完全相同的重复行、`(类型,载荷)` 重复、以及极少数 **已被靠前 `DOMAIN-SUFFIX` 盖住** 的 `DOMAIN`。
- **`DOMAIN-KEYWORD` 早于大量后缀：** 典型如油管相关关键词写在极前部，其后大量后缀/分组对「含该关键词的主机」**不再起作用**——反哺我们自有模板时应避免「以为后面后缀能纠错」的假安全感。

## 值得反哺到 Extend 模板（`extend/*-rule-split-extend.yaml`，默认机场稿）方向的点

1. **两类默拒分组并用：** 在机场稿里，`🛑` / `🍃` 都是 `select`，默认可选 `REJECT`，也可临时改成 `DIRECT` 排查；自建模板可把 **广告** 与 **应用遥测** 拆成 **两个策略组**，分别挂 `RULE-SET`/`GEOSITE` 或由本地片段注入，以利灰度。
2. **高优先级补丁域前置：** AI、自用门户、邮局 `DOMAIN` 写在 **GEOIP/`MATCH`** 与大段后缀表之前——与你们在扩展稿里强调的「书签式补丁优先」一致，可继续沿用 **MECE 分段注释**。
3. **大厂「直连补丁」后缀表：** 稿末对谷歌系一批 **可走直连** 的 `DOMAIN-SUFFIX` 与前面「走节点」的规则并存——靠 **先后顺序** carve-out；若我们模板里用大标签（如 `GEOSITE,google`），需要同样 **先写例外再写大块**。
4. **阶段产物安全：** 含 `proxies` 的成品一律 **`*.local.yaml`**，避免误入 Git；反哺用 **分段片段**时可只导出 `rules:` 切片或统计数据。
